# 0017 — kbuild: ubsan: skip UBSAN for external modules by default

**File:** `patches/0017-kbuild-ubsan-extmod-opt-in.patch`
**Touches:** `scripts/Makefile.lib`, 2 lines changed
**Authored as:** `Ferran <ferran.duarri@me.com>`
**Real commit:** `b2c8fd0de75d` in `~/Dev/kernel_inference/linux`

## What it changes

External modules built with `KBUILD_EXTMOD` set currently inherit UBSAN
sanitizer flags from the kernel's own `KBUILD_CFLAGS`, because
`is-kernel-object` evaluates to `y` for any `obj-m` object regardless of
whether that object belongs to the in-tree kernel or a third-party
out-of-tree module. This patch makes UBSAN opt-in for external modules: the
`is-kernel-object` fallback is skipped whenever `KBUILD_EXTMOD` is set. A
module that explicitly wants UBSAN can still opt in with `UBSAN_SANITIZE :=
y`. In-kernel module builds are entirely unaffected — the change is gated on
`KBUILD_EXTMOD` alone.

## Why

Real, observed breakage: VMware's `vmnet`/`vmmon` external modules trigger
UBSAN undefined-behavior checks at runtime when built against a
UBSAN-enabled kernel, causing packet-forwarding failures and VM instability
— the module itself still loads successfully, so the failure mode is silent
until traffic actually flows through it. UBSAN was never meant to police
third-party source the local build has no control over; it exists to catch
UB in code the kernel maintainers can act on.

## Verification

Two-line, single-condition Makefile change (`$(if $(KBUILD_EXTMOD),,...)`
wrapped around the existing `is-kernel-object` reference in two places).
Builds clean in this tree at commit `b2c8fd0de75d`.
