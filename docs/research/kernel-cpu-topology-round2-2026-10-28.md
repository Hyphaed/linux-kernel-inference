# Kernel and CPU topology levers, round 2: 2026-10-28

Scope: preemption model, HZ, hybrid P/E scheduling, inference thread pinning, idle states, in-flight kernel work. Box: i9-14900KF, kernel 7.2.12-hyphaed. Nothing here was applied. Round 1 is `workstation-perf-tuning-2026-10-28.md` (not repeated).

Tags: **VERIFIED** = I opened the source (page, lore/lkml mirror, or this tree's code). **PROBED** = read from this machine today. **INFERENCE** = my reasoning from verified facts. **UNVERIFIED** = search snippet only. Anything older than 2025 is marked "possibly stale". Numbers that do not exist are said not to exist.

## Headline findings

1. **sched_ext is in charge of every fair task here, so most scheduler knobs do nothing right now.** `/sys/kernel/sched_ext/switch_all` = 1 and ops = `bpfland_1.1.2` [PROBED]. In this tree `kernel/sched/ext/ext.c` only ever calls `resched_curr()` (lines 1520, 2680, 3699, 5827, 8556, 8577) and never `resched_curr_lazy()`; the lazy flag is raised only from `fair.c` (lines 2304, 10254) [VERIFIED, read in `build/linux-7.2.10`]. Consequence: a lazy-vs-full A/B with bpfland running mostly measures nothing. EEVDF `base_slice_ns`, BORE, `SCHED_MC_PRIO`/ITMT asym packing and `SCHED_CACHE` all live in the fair class and are bypassed too (INFERENCE from switch_all=1). Any scheduler A/B must stop `hyphaed-scx` first.
2. **The CPU only has C1 to idle in.** `cpuidle` driver `intel_idle`, states are `POLL` and `C1_ACPI` only (latency 1 us, residency 1 us), governor `menu` [PROBED]. No C1E/C6/C8/C10 is exposed to the OS. The 2023 lkml thread on Raptor Lake says intel_idle has no custom RPL table and relies on BIOS `_CST` [VERIFIED via search result text, possibly stale as to current code]; so the BIOS is handing the kernel a C1-only list, or deep C-states are disabled in BIOS. Round 1 never listed this, and its R17 (`teo` governor) is moot with two states. See candidate 6.
3. **Cache-aware scheduling is compiled in (`CONFIG_SCHED_CACHE=y`) and inactive on this CPU by design.** `sched_cache_set()` turns `sched_cache_present` on only when the topology has more than one LLC, and the active switch needs it [VERIFIED, `kernel/sched/topology.c` 947-1045]. The i9-14900KF has one 36 MiB L3 (E-core L2 clusters are not LLCs), so it never activates. The fresh lead "cache-aware scheduling for this topology" is a dead end.
4. **Lazy preemption evidence is thin and splits on jitter vs throughput.** Detail under candidate 1.

### Notes

1. **Lazy vs full evidence, all of it:**
   * Design (LWN, 2024-10-18, VERIFIED): lazy is far less likely to preempt a running fair task than full; the tick promotes the lazy flag; RT wakeups still preempt immediately; early test by Galbraith had lazy throughput "just short of" voluntary.
   * Peter Zijlstra's patch (Phoronix 2026-01-14, VERIFIED): x86 now offers only full and lazy in 7.0; lazy is "the recommended setting", no benchmark in the commit message.
   * s390 KVM/OVS/uperf: up to 50% lower throughput on lazy, guest CPU time 16% to 9%, TCP retransmissions up to 30x; reporter reached no cause (lkml, Ciunas Bennett, 2026-02-24, VERIFIED). Network path, not ours, but a warning for the VM and Docker bridge traffic here.
   * CachyOS issue #339 (VERIFIED, 2024-11 to 2026-05): mesa compile 424.44 s full vs 422.65 s lazy (2025-01-06, confounded by non-preemptible RCU that was later found); another poster 37m32s full vs 38m39s lazy wall (2025-03-07); 2026-05-04 tbench about +3% throughput with lazy but about 300% more jitter measured with `rtla` and worse frametime variance in games (single poster, no raw data); 2026-05-03 a poster reported much better lazy FPS in Cyberpunk 2077 but compared across kernels, so invalid. CachyOS kept full as default and re-enabled PREEMPT_DYNAMIC.
   * No controlled lazy-vs-full benchmark on Raptor Lake, on a hybrid CPU, or with Sunshine/NVENC streaming exists that I could find. None on llama.cpp either.
   * Reading for this box: you currently run `full` with scx owning tasks, so lazy would change little (headline 1). Stop scx for a fair test. Since the stream and cyclictest cores 4-7 are jitter-sensitive, the one tool that matters is `rtla timerlat`, not throughput.
2. **Why `-C 0x5555`:** the P-core SMT pairs are (0,1), (2,3) ... (14,15) [PROBED: cpu0 core_cpus_list 0-1]. Even-numbered CPUs give one hardware thread per P-core. `-t 16 -C 0xFFFF` uses both SMT siblings. E-cores are 16-31, L2 shared in groups of 4 (cpu16 `index2/shared_cpu_list` 16-19 [PROBED]).
3. **Raptor Lake `cpu_capacity`:** reads 1024 on both a P and an E core [PROBED]. Capacity-aware hybrid scheduling in the 2024 intel_pstate series is documented as for hybrid non-SMT systems [UNVERIFIED snippet, Phoronix, possibly stale]; on this SMT part ITMT asym packing is the mechanism, and under scx it is not used.

## Contradictions and corrections to round 1

* M12 treated scx as one A/B among many. It is bigger: with switch_all=1 and `resched_curr()` only in ext.c, it silently disables the fair-class knobs that round 1's R1 (ITMT), R5 and the EPP discussion assumed. Run every scheduler or preemption A/B with `hyphaed-scx` stopped, or the result is an scx result.
* R17 (cpuidle `teo`): irrelevant. Only POLL and C1_ACPI are exposed, so governor choice has nothing to choose between.
* Round 1 did not mention cache-aware scheduling. It exists in this 7.2 kernel but cannot activate on a single-LLC part.
