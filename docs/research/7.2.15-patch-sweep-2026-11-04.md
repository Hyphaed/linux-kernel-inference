# 7.2.15 patch sweep and the 7.3 scheduler backport (2026-11-04)

7.3.1 isn't settled enough to boot yet, so this round readies 7.2.15 instead and asks what of 7.3's scheduler work can
be carried back. Labels: **measured** (ran here), **read** (read the code), **inferred**, **not checked**. Nothing here has
run on a booted 7.2.15; the A/B comes after the install.

## The series on 7.2.15

The default `kernel-org-7.2` series applies unchanged on v7.2.15: sequential `git am --3way` plus 32 touched objects
compiled, with and without `series.experimental` (**measured**, stage 30). `out/sweep/7.2.15/` holds the sweep
(842 bullets, includes the zen/liquorix/Google/AMD/Valve fork-only sections added for 7.3.1).

## Intel's hybrid-core fixes: portable, but they won't do anything on this CPU

The Intel work in 7.3 is Ricardo Neri's six-patch series (cluster balancing on asymmetric-capacity domains). Status on v7.2.15:

| Patch | On 7.2.15 |
|---|---|
| Do not skip CPUs of similar capacity with busy SMT siblings (180ff97c) | applies, `custom/0031` |
| Also gate overloaded status update for SD_ASYM_CPUCAPACITY | already in 7.2.15 (same code is there) |
| Check CPU capacity before comparing group types | already in 7.2.15 (the block is already ahead of the group-type compare) |
| Skip misfit load accounting when the destination CPU cannot help | applies, `custom/0032` |
| Allow load balancing between CPUs of identical capacity | applies, `custom/0033` |
| Restore SD_PREFER_SIBLING in asymmetric-capacity domains | applies, `custom/0034` |

All four, plus Andrea Righi's SMT-aware NOHZ balancing (`custom/0035`), sit in `series.experimental`.

**What they cost you in practice: nothing, because they're gated on `SD_ASYM_CPUCAPACITY` and this machine never sets
it.** `intel_pstate` only turns on asymmetric-capacity scheduling for a hybrid CPU when SMT is off (the source says so:
"do not do that when SMT is in use"); the 14900KF has SMT, so it stays on ITMT asym-packing. `cpu_capacity` reads 1024 on
every CPU including the E-cores (**measured**, sysfs). Same condition in 7.3.1 (**read**). To confirm on your side:

    sudo grep -H . /sys/kernel/debug/sched/domains/cpu0/domain*/flags

You should see `SD_ASYM_PACKING` and no `SD_ASYM_CPUCAPACITY`. Only 0035 (SMT-aware idle balancing) can change anything here.

## The 7.3 feature that 7.2.15 lacks: the single-runqueue EEVDF fair class

Mainline v7.3's scheduler headline (Phoronix: a game's minimum frame rate 3.8 -> 20.6 fps under eight heavy background
processes, Zijlstra's test; **not checked** here) is "sched/eevdf: Move to a single runqueue" (85570f10a4c6) with the
`cgroup_mode` switch (up/max/concur/tasks, default `concur`), Vincent Guittot's short-slice/slice-protection series and
"Fix flat hierarchy". It keeps the cgroup hierarchy for load tracking but runs EEVDF on one flat `rq->cfs`, which is what
helps a game sitting in its own systemd scope next to a CPU hog.

It can't be cherry-picked: 17 of the 44 commits touching `fair.c` fail in order because they need other 7.3 changes.
What works is a file transplant plus the few outside APIs it needs, as four patches in `patches/kernel-org-7.2/series.sched73`
(opt-in with `HYPHAED_SERIES_VARIANT=sched73`; the default series is untouched):

| Patch | What it carries |
|---|---|
| `custom/0036-cgroup-task-migrate-notifier-7.3-for-7.2` | `cgroup_task_notifier` + `cgroup_common_ancestor()` (cgroup.h/.c) and `cpuset_num_cpus()` (cpuset.h/.c), only the hunks that mention them |
| `custom/0037-sched-ext-v7.3-for-7.2` | all of `kernel/sched/ext/`, `include/linux/sched/ext.h`, the sched_ext tracepoint header, the scx hunks of `sched.h`/`idle.c`/`build_policy.c`; one adaptation: `kernel/rcu/tree_stall.h` passes `cpu_none_mask` to `scx_rcu_cpu_stall()` because 7.2's RCU has no stalled-CPU mask (a stall report that aborts a BPF scheduler won't name a CPU in its message; the abort still happens) |
| `custom/0038-sched-v7.3-single-runqueue-for-7.2` | `fair.c`, `core.c`, `debug.c`, `sched.h`, `topology.c`, `pelt.c`, `psi.c`, `sd_flags.h` from v7.3.1 plus `sched_entity::h_load`; `fair.c` drops the `hrtimer_bases.h` include (7.3 moved `hrtimer_callback_running()` there, 7.2 has it in `hrtimer.h`) |
| `custom/0001-cachyos-bore-7.3-on-7.2` | the CachyOS 7.3 BORE, written against that `fair.c`; only the `struct bore_ctx` anchor in `sched.h` differs from `0001-cachyos-bore-7.3` |

Left out on purpose: `cpufreq_schedutil.c` and the cpufreq `adjust_perf()` `max_perf` argument (only schedutil uses it,
sched_ext doesn't), and every unrelated 7.3 change in `include/linux/sched.h` (renamed `mm_exit_exec_release`, `real_fs`,
`ipi_mask`) that would break the rest of the tree. Do not stack `series.experimental`'s 0031-0035 with this; 0038 already
contains them.

Evidence (all **measured**): the variant series applies on v7.2.15 and 41 touched objects compile (stage 30); all of
`kernel/sched/`, `kernel/cgroup/`, `kernel/` and `mm/` compile; **a full `vmlinux` build and link succeeds** (491 MB, with
the running kernel's config, `CONFIG_SCHED_CLASS_EXT=y`). Two things only the full build found, now fixed: `fair.c` is its
own object in 7.2 and stage 30 used to skip it (it compiles standalone objects now), and `cpuset_num_cpus()` is a 7.3-only helper.

**Not checked:** modules and the initramfs, boot, whether the 7.3 `sched_ext` and the new `fair.c` behave together at runtime
(including the BPF struct_ops paths), the `cgroup_mode` default under your systemd scopes, and any performance claim. This is
experimental by ADR-009 and promotes only after the two-run A/B.
