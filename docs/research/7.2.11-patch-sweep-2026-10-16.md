# 7.2.11 patch sweep (2026-10-16)

Labels: **measured** (command run this session), **read** (source or file read), **inferred**, **not checked**.

## Nothing in the sweep changes what we carry

The series is unchanged: 26 patches in `patches/kernel-org-7.2/series`. `30-validate-series.sh` applied all of
them with a sequential `git am --3way` on v7.2.11 and compiled the 32 objects they touch, no conflict and no
error (**measured**, `series validated on v7.2.11`). The script also lists four files as "drifted under a patch"
(`dm-crypt.c`, `dcache.c`, `fork.c`, `sched.h`): same hunks that shift offset on every stable bump,
they still apply, so that's context movement and not a conflict.

`candidates.md` has 476 bullets across XanMod, CachyOS, tkg, kernel-research, the Intel overlay, SteamOS, the
stable queue and the v7.2..v7.3-rc7 mainline paths. The mainline half is v7.3-rc7 content that reaches us through
stable anyway. I read the mainline list and the stable-queue list in full (**read**); the per-source sections I
filtered for the paths this box runs (sched, mm, nvme, pci, x86, dma-buf), not line by line.

## Boot log of the 7.2.10 boot, same day

The sweep isn't the only thing this round found. `journalctl -b -p warning` on 7.2.10-hyphaed showed two real
problems and a handful of noise lines (**measured**).

* **`nvidia_fs` wouldn't load** (`disagrees about version of symbol nvidia_p2p_*`). The 7.2.10 DKMS build log says
  `Using nvidia DKMS Module.symvers: .../7.2.9-hyphaed/...`: `Makefile:111` calls `create_nv.symvers.sh` with no
  kernel argument, so building for a kernel you aren't running takes the running kernel's CRCs. It's the same bug
  `diagnostics/fix-nvidia-fs-symvers.sh` was written for; that script was never run for 7.2.10, and the Makefile is
  still unpatched. GDS has been in POSIX fallback all boot. Running the script patches the Makefile once, so the
  7.2.11 autoinstall is built correctly too.
* **`/etc/fstab` lists `/swap.img` twice**, so `systemd-fstab-generator` exits 1 each boot. Swap itself works.
* Three memcg OOM kills, all inside user scopes (`invest-gpujob-fast-model`, two `run-*` scopes): the cgroup
  limits doing their job, not a kernel fault. Not touched.
* `snap.firmware-updater.firmware-notifier` fails its start limit; `scx_bpfland` logs the "writing directly to
  `p->scx.slice` is deprecated" warning (userspace scheduler, not the kernel). Neither affects the workloads.
* Noise, left alone: `VK_SUBOPTIMAL_KHR` from Nautilus, a gnome-shell stack-position assertion, UFW dropping
  Steam LAN discovery on the vmnet interfaces, `TDX not supported by the host platform`.

Both fixes are in `diagnostics/fix-boot-7.2.10-2026-10-16.sh` (needs root). It reuses the existing nvidia-fs fixer
and removes the duplicate fstab line, with a backup.
