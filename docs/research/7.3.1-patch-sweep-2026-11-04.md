# 7.3.1 patch sweep and verdicts (2026-11-04)

Targeted tier (owner choice), not a full hyperresearch run. Sources: the sweep in `out/sweep/7.3.1/candidates.md`
(614 bullets after the fork-only filter), Phoronix/LWN-based 7.3 coverage, the NVIDIA/Fedora threads on 7.3-rc, and
the code in `build/validate-7.3.1`. Labels: **measured** (ran here), **read** (read the code or log), **inferred**,
**not checked**. Nothing below is an A/B result; the A/B comes after the 7.3.1 boot.

## What changed since the carried-over series

The `kernel-org-7.3` series had been copied from 7.2.12 on 2026-10-31 and never run. Run on v7.3.1 it failed at the
first patch. Three of the 26 patches needed work, the other 23 applied unchanged (**measured**, stage 30: sequential
`git am --3way`, then 31 touched objects compiled, "series validated on v7.3.1").

| Patch | What broke on 7.3.1 | What was done |
|---|---|---|
| 0001 BORE | the 7.2 file fails in `kernel/sched/fair.c` (base-slice hunk moved) | replaced by CachyOS's own 7.3 file (`kernel-patches` 2b4e3ce8, 2026-09-09). It assumes `CONFIG_CACHY` around two `fair.c` declarations, which vanilla doesn't have; the hunk was re-cut without it. New file `custom/0001-cachyos-bore-7.3.patch`. Unlike the 7.2 port it also touches `kernel/sched/build_utility.c` (includes `bore.h`). |
| 0023 cache_ext | 5 hunks rejected | include context in `memcontrol.h`/`memcontrol.c`/`vmscan.c`, and `kernel/bpf/verifier.c`, where `check_kfunc_call` is now one `if` per callback kfunc instead of an `else if` chain. Re-anchored, same logic. `custom/0023-...-7.3.patch`. |
| 0024 apparmor userns | `apparmor_userns_create()` rejected | 7.3 still uses `begin_current_label_crit_section(&needput)`; the 7.2 version of the patch dropped the argument. Re-cut with the `needput` form. `custom/0024-...-7.3.patch`. |

0023 and 0024 compile (both in the 31 objects) but **not checked**: whether the cache_ext hooks fire at runtime. That
was already unproven on 7.1.10 and 7.2 and stays unproven. The verdict on keeping it in the default series is the
same as before: it is there, it is inert without a BPF program, and it needs a real workload to earn the slot.

## Candidates by source

**Zen** (`github/vendors/zen`, new this round). There's no `7.3/main` yet; the `7.3/*` branches are four topic series.

* `mglru-fg-v4` (Kairui Song, 31 commits, MGLRU frequency-guided promotion). **Reject for now.** It rewrites the
  same `vmscan.c`/memcg paths our 0023 and 0025 sit on, it's v4 on the list and unmerged, and the only workload that
  would show it is page-cache pressure during model loads, which nobody has measured here. Revisit when it lands in
  mm-akpm; if it does, 0025 may become redundant.
* `prjc` (100 commits, Project C PDS/BMQ). **Reject.** A second scheduler next to BORE; the only interesting part is
  the "auto-detect heterogeneous CPU topology" commit, and nothing says it beats BORE on 8P+16E.
* `zram-zcomp-v5` (14) and `zswap-contention-v4` (3). **Wait for mainline.** This box does run zswap (`enabled=Y`) and
  an 8 GB zram swap, but zram holds 26 MB of 8 GB and `/swap.img` is at 0 B: no contention to fix (**measured**
  from `swapon --show`).

**Liquorix** (`github/vendors/liquorix`). Newest branch is `7.2/master`; no 7.3 yet. Nothing to take; its patch set is
zen's plus config. Re-check at 7.3.2.

**CachyOS.** BORE as above. `prjc` and `handheld`/`rt-i915`/`aufs` directories: reject (second scheduler; hardware we
don't have; aufs). nvidia-580xx patches: irrelevant, we're on 615. The "7.3: NVIDIA D3 state fix" (#1096/#191) is a
runtime-D3 fix for laptops with hybrid graphics: **not checked** whether the Omen needs it; park it for the laptop pass.

**XanMod.** The XanMod commits we pin (0003-0011, 0018, 0025-0027) all applied on v7.3.1 without a re-anchor. Not carried: netfilter fullcone/FLOWOFFLOAD, tcp collapse sysctl, binder-as-module,
Steam Deck MFD/hwmon drivers (hardware absent), `sysctl` for unprivileged CLONE_NEWUSER (we have our own 0024 apparmor
restriction and don't stack a second policy knob).

**Google.**
* BBRv3 (`google/bbr` branch `v3`, 27 commits, plus iproute2 patches). **Reject.** BBRv3 was dropped on 2026-08-27 and the 7.2 series records why it stays out (BBRv1 + fq stays active through
  `configs/fragments/50-net-bbr-fq.config`); Google's tree doesn't change that. The Shield stream is Sunshine/NVENC over RTP/UDP on a 1 GbE LAN (ADR-008), where TCP congestion control
  isn't in the path (**inferred**). No number, no patch.
* `android18-7.3`, `android-mainline` (90 + 41 fork-only commits). **Reject** the vendor hooks, ashmem, binder,
  gki_defconfig. One lead worth a line: the proxy-execution series (`SCHED_PROXY_EXEC`, now allowed with sched_ext).
  The option exists in mainline; whether it helps a desktop under BORE is **not checked** and needs an A/B on the
  game workload, so it is a config candidate, not a patch.
* ChromeOS kernel: newest branch `chromeos-6.12`, nothing for 7.x.

**NVIDIA.** Newest open-gpu tag is 615.78.08, which is what we run, so there's no newer driver to take.
**Measured:** all C objects of 615.78.08 compile against v7.3.1's headers (stage 35: zero `error:`). The Fedora
thread about 615.71.09 failing on 7.3-rc3 does not reproduce on 615.78.08 with the final 7.3.1 headers. Not proven:
the link step. My test tree had no `Module.symvers`, so modpost reported `alloc_pages_node_noprof` and three
`__drm_atomic_helper_*_state_init` symbols as undefined; I checked and 7.3.1 does export them, so that is the test
tree, not the driver. The real answer comes from the `nvidia` phase after the kernel build.

**AMD** (laptop only). `amd-staging-drm-next` (100 commits, display/DC firmware promotion, DSC/USB4) is the 7.4 queue,
not a 7.3 fix list; no backport on a desktop-first project. `pdx86 for-next`: 0 fork-only commits, everything is already
in the mainline mirror. 7.3 itself carries the Zen 6 prep and per-CCD EPYC temps, neither relevant to a Ryzen AI 9.

**Intel.** Mainline v7.3.1 already contains Intel's E-core cluster load-balancing fix (Ricardo Neri) and the rc2
cache-aware-scheduling misfit fix for hybrid CPUs (Tim Chen). Nothing to carry; this is the reason to boot 7.3.1 and
measure. The Intel overlay has no 7.3 tag (0 commits). New config symbol worth an A/B, **not changed**:
`CONFIG_SCHED_CACHE` (default y, "cache aware load balance"). It groups a process's threads in one LLC; the
14900KF has a single 36 MB L3, so it should be a no-op here (**inferred**) and there is a runtime switch in debugfs
(`sched_cache_enable_write` in `kernel/sched/debug.c`) to test it on one boot.

**Valve / SteamOS.** The Valve sweep was broken until today: the old fetch wrote only FETCH_HEAD, so `origin/7.3/integration`
never existed and the report said "0 commits". Fixed in `10-sync-sources.sh`. Real content (300 commits, all tagged
`NOT-FOR-UPSTREAM`/`FROM-ML`/`FOR-UPSTREAM`): handheld HID (Lenovo Go S, OneXPlayer), ASUS Ally fan curves, rtw89 Wi-Fi,
hibernate speedups, amdgpu soft-evicted BO fixes (Steam Deck). **Reject all** for this box. NTSYNC: mainline since
6.14 and already built as a module here (`configs/fragments/43-ntsync.config`); Valve shipping it in SteamOS 3.7.20 is packaging news, no patch.

**Linux kernel (mainline / stable).** Stable-queue `queue-7.3` holds 139 patches for 7.3.2 (io_uring cancellation,
keys, driver-core locking). Not carried; we take them when 7.3.2 is tagged. Notable 7.3 mainline items that arrive
for free: scheduler "flatten the pick" and lower short-slice latency, nested sched_ext, DRM TTM + dmem cgroup
eviction, MM latency work. Phoronix's own test claims a minimum-frame-rate gain on a heavily loaded game; **not checked**
here, which is exactly what the 7.2.14 vs 7.3.1 A/B should answer.
